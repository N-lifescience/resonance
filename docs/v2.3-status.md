# v2.3 현황 (2026-10-23, v2.3.0 — 배포 전)

사용자 요청(10-23, `맥미니_작업요청.md`): 실시간 공유 기능으로 수업해 보고 나온 피드백 네 가지를 고친다. main에 바로 올리지 않고 선생님께 결과를 보인 뒤 배포한다.

## 1. 응답 현황 「접속 m명 중 n명 제출」 (`68-live.js`, `86-live.css`)

- 교사 화면 오른쪽 위에 칩이 뜬다. 학생이 답하는 활동(퀴즈, 투표, 단답, 슬라이더)이 있는 장에서만 보인다. 누르면 「학생 보기」가 열린다.
- 분모는 지금 접속한 학생(`count()`, 최근 30초 안에 소식이 온 학생)이다. 분자는 그 장의 활동 가운데 하나라도 낸 학생이다. 여러 활동에 낸 학생도 한 명으로 센다. 나간 학생은 분자에서도 빼서 n이 m을 넘지 않는다(`LiveCore.answered`).
- 퀴즈, 투표, 단답이 있으면 '제출', 슬라이더만 있으면 '참여'로 쓴다. 모두 내면 「접속 28명 모두 제출」로 바뀌고 초록이 된다.
- 실시간 창이 열려 있으면 칩을 숨기고 창의 인원 줄에 같은 글을 쓴다. 활동이 없는 장에서는 창에 「접속 28명」만 쓴다(전에는 「참여 28명」).
- 툴바 타이머와 겹치면(좁은 화면, 옮긴 타이머) 칩이 타이머 아래로 내려간다.

## 2. 툴바 「타이머」 (`62-timer.js` PopTimer, `81-timer.css`, `30-toolbar.js`)

- 툴바 오른쪽 묶음에 「타이머」 단추를 넣었다. 판서를 꺼도 남는다.
- 창: 30초, 1분, 2분, 3분, 5분, 10분은 누르면 바로 간다. 「직접 정하기」는 − + 로 1~60분을 맞추고 「시작」. 타이머가 떠 있으면 「타이머 닫기」도 보인다.
- 화면 위 가운데에 뜬다. 멈춤(이어서), 다시, +1분, × 단추. 끝나면 '끝'과 함께 세 번 깜빡인다(장 안 타이머와 같은 규칙). 장을 넘기거나 칠판을 열어도 남는다. 단추가 아닌 곳을 끌면 옮겨진다. 펜을 든 채로도 판서가 되지 않는다(`data-no-ink`).
- 시계는 장 안 타이머(`Timer`)의 함수를 같이 쓴다. `Timer.add`(시간 늘리기), `Timer.wire`(학생에게 보낼 모양)를 더했다.
- 실시간 수업 중이면 교사 상태(`state`)에 `timer: { left: 남은 ms, total: 초, run }`을 싣는다. 학생 화면 오른쪽 아래에 「남은 시간 2:31」이 보인다. 멈추면 「멈춤」, 끝나면 「시간 끝」이다. 기기마다 시계가 달라 끝 시각 대신 남은 시간을 보내고, 학생은 받은 때를 기준으로 끝 시각을 다시 잡는다. 상태가 5초마다 오므로 그때마다 다시 맞춘다.
- 받은 값 검사(`LiveCore.clean`): `left` 정수 0~1억, `total` 정수 1~10만, `run` 참거짓. 하나라도 틀리면 타이머를 없는 것으로 본다. 옛 학생 화면(v2.2)은 이 값을 버리므로 그대로 돈다.
- 학생 데이터는 늘지 않는다. 교사 → 학생 방향의 값이고 이름·응답이 없다.

## 3. 분반별 판서 (`30-toolbar.js`, `30-toolbar.css`)

- 선생님 선택(10-23): 「반 단추 눈에 띄게」만. A~E반 미리 넣기와 화면 구석 표시는 고르지 않았다.
- 툴바 「반」 단추의 반 이름을 주황 알약으로 보인다. 왼쪽·오른쪽 붙임에서는 다른 단추 이름이 숨지만 반 이름은 남는다.
- 반이 바뀌면(목록에서 고르기, 지금 반 삭제) 화면 가운데에 「B반 판서로 바꿨어요」가 2초쯤 떴다가 사라진다(`Toolbar.notice`, `role="status"`).
- 판서는 전처럼 반마다 이 기기의 IndexedDB에만 둔다. DB는 쓰지 않는다.

## 4. 응답 장에서 넘기기가 막히던 문제 (`12-nav.js`, `56-quiz.js`)

- 재현(헤드리스 크롬, 실제 키·마우스 입력): 단답 입력칸에 포커스가 있으면 리모컨 PageDown과 → 가 무시됐다(`Nav.onKey`가 입력칸 안의 키를 모두 버림). 빈 칸으로 「보내기」를 누르면 엔진이 입력칸으로 포커스를 되돌려 같은 일이 생겼다. 툴바 ▶ 클릭과 터치는 넘어갔다. 퀴즈·투표 보기는 누른 뒤 포커스를 놓아서 문제없었다. 익스플로라그램 슬라이더는 손을 떼면 포커스를 놓아서(`58-calc.js`, `51-stepper.js`) 문제가 없었다.
- 고친 것:
  - 장 안 글 입력칸에 포커스가 있어도 PageDown·PageUp(리모컨)은 넘기고 칸을 놓는다. 빈 칸에서는 화살표도 넘긴다. Esc는 칸만 놓는다. 글이 든 칸의 화살표, 글자, Space, Enter, Backspace는 그대로 글쓰기다. 엔진 창의 입력칸(반 이름, 코드)은 장 밖이라 손대지 않는다(`Nav.fieldNav`).
  - 장을 떠날 때 그 장 안에 포커스가 있으면 놓는다.
  - 단답 「보내기」: 빈 칸이어도 교사 화면에서는 입력칸에 포커스를 두지 않는다(전자칠판 화면 키보드가 뜨고 리모컨이 막힌다). 학생 화면은 전처럼 입력칸으로 보낸다. 보낸 뒤에는 칸을 놓는다(단추를 눌러도 포커스가 칸에 남는 사파리).
  - div로 만든 퀴즈 보기(role=button)도 누른 뒤 포커스를 놓는다.
