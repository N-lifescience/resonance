# v2.5 현황 (2026-10-26, v2.5.0 — 배포 전)

사용자 요청(10-26): 실시간 수업에서 나온 세 가지를 고친다. ① 실시간 창의 작은 QR을 누르면 화면 가득 크게. ② 칠판에 쓴 판서가 학생 태블릿·휴대폰에서 안 보인다. ③ 익스플로라그램 장의 판서는 학생 화면에 잘 맞는데 다른 장의 판서는 살짝씩 밀린다(학생 태블릿 사진 첨부: 「마이토콘드리아의 구조와 기능」 10장).

## 1. QR 크게 보기 (`68-live.js` `showBig`, `86-live.css`)

- 실시간 창의 QR을 단추로 바꿨다. 아래에 「눌러서 크게 보기」가 붙는다.
- 누르면 화면 가득 QR(세로 64%), 방 코드, 학생 안내 한 줄이 뜬다. 아무 데나 누르거나 「닫기」, Esc, 장 넘기기로 닫는다. 「끝내기」를 누르면 함께 닫힌다.
- 크게 띄운 화면은 무대 밖이라 펜을 든 채 눌러도 판서가 되지 않는다(`data-no-ink`).

## 2. 칠판 판서가 학생 화면에 안 보인다

- 재현하지 못했다. 이 PC의 두 탭(로컬 전송)과 실제 Supabase 경로, PC·휴대폰(375px) 크기, 늦게 들어온 학생 모두 칠판과 칠판 판서가 학생 화면에 그려졌다.
- 그래서 학생이 못 보고 지나치는 경로를 막았다. 지금까지는 지난 장을 보던 학생에게 교사가 칠판을 열면 위 띠(「선생님은 칠판 화면」)만 떴다. 이제 교사가 칠판을 열거나 다른 칠판 쪽으로 넘기면 그 학생도 칠판으로 데려온다(`onMain`의 `toBoard`). 칠판을 닫을 때는 보던 장에 둔다.
- 전자칠판 자체 펜(판서 끈 상태)이나 다른 화이트보드 프로그램에 쓴 것은 여전히 보낼 수 없다.

## 3. 판서가 학생 화면에서 밀린다

사진 분석: 왼쪽 글 위 동그라미(이중막, 크리스타, 바탕질)는 맞고, 그림 이름표와 ② 문장 위 동그라미만 어긋났다. 학생 화면의 장 모양이 「편집」으로 옮기기 전 모양이었다. 그림 상자 `translate: 68px -8px`, 그림 설명 `333px 5px`, ② 문장 `-485px 43px`가 빠진 모양을 이 PC에서 그리면 사진과 같다. 교사 판서는 무대 좌표(1280×720)로 오가므로 장 모양이 다르면 빗나간다. 익스플로라그램 장은 편집으로 옮긴 요소가 없어 맞았다.

옮김이 빠지는 경로는 둘이다.

- 학생 브라우저가 CSS `translate` 속성을 모른다(크로뮴 104·삼성 인터넷 20·사파리 14.1 이전). 업데이트를 막아 둔 학교 태블릿이면 그렇다.
- 학생이 연 파일이 교사 화면과 다르다. 사이트에 올린 파일(Blob `1792980003886.html`)은 10-26 11:00:03에 올라갔고 내려받은 파일 저장 시각은 10:59:37이다. 수업 중 「편집」으로 옮겼다면 그 전에 연 학생 화면에는 옮김이 없다.

고친 것:

- `15-compat.js`(새 파일): `CSS.supports('translate', …)`가 거짓인 브라우저에서만, 장이 보일 때 `style="translate: X Y"`(px) 요소를 같은 거리만큼 옮긴다. 흐름 속 요소는 `position: relative`와 `left`·`top`, 떠 있는 요소는 한쪽 여백에 더하고 반대쪽에서 빼서 폭을 그대로 둔다(그림 설명처럼 `left: 0; right: 0`인 요소가 두 줄로 바뀌지 않게). SVG 속 도형은 `transform` 속성에 붙인다. 원본(Source)은 그대로라 저장 파일은 바뀌지 않는다. 숨은 장은 auto 여백을 px로 알려 주지 않아 `show` 때 한 번 맞춘다.
- 수업 중 편집은 코드로 학생에게 보내지 않는다(검증 안 된 HTML을 채널로 보내게 된다). README에 「저장해 다시 올리기 전까지 학생 화면에 보이지 않는다」를 적었다.

같은 증상을 내는 셋째 경로도 고쳤다. 엔진 글꼴은 Pretendard를 먼저 찾지만 불러오지 않아 기기마다 글꼴이 다르다(윈도 맑은 고딕, 맥·아이폰 Apple SD 산돌고딕, 갤럭시 삼성 글꼴). 넘친 장을 줄이는 배율(Fit)이 기기마다 달라진다. 이 수업 10장은 글꼴만 바꿔도 1, 0.971, 0.902가 나왔다. 줄이면 장 안 배치 폭도 넓어져 오른쪽 그림 칸이 옮겨 가므로 판서가 빗나간다.

- 교사는 상태(`state.ink.z`)와 판서 묶음(`ink.z`)에 그 장의 배율을 싣는다(`zoomOf`). 늦게 뜬 글꼴·그림으로 다시 줄이면(`fit` 이벤트) 상태를 다시 보낸다.
- 학생은 교사 배율이 더 작으면 그 배율로 맞춘다(`Fit.capTo`). 학생 기기가 더 줄여야 하면(글꼴이 더 넓음) 글이 잘리지 않게 학생 배율을 둔다. 이 경우에는 여전히 조금 어긋날 수 있다.
- 처음에는 학생 판서를 (학생 배율 ÷ 교사 배율)로 키우거나 줄여 그렸는데, 배치 폭이 바뀌는 장에서 더 어긋나 되돌렸다.
- 실측(이 수업 10장, 교사 AppleGothic 0.83 · 학생 Pretendard): 맞춘 뒤 이름표 자리 차이 2~6px. 맞추기 전에는 가로 약 100px, 세로 약 83px.

## 시험

- 단위 106 통과(바뀐 것 없음).
- 브라우저 42파일 모두 통과. 새로 넣은 것:
  - `live.test.html`: QR 크게 보기(누르기, 코드, 크기, 아무 데나 누르기, Esc).
  - `live-ink.test.html`: 지난 장을 보던 학생을 칠판으로 데려오기(새 칠판 쪽, 다시 열기, 닫을 때는 두기), 교사 배율에 맞추기(오른쪽 이름표가 두 화면 무대 같은 자리, 학생이 더 줄여야 하면 학생 배율, 교사 배율이 돌아오면 다시 재기).
  - `compat.test.html`: translate를 걷고 맞추면 흐름 속 문단, 상대 위치 상자, 떠 있는 이름표, 양옆을 붙인 설명, SVG 도형, 뒤 문단이 모두 같은 자리.
  - `compat-old.test.html`: `CSS.supports`와 translate를 막은 옛 브라우저 흉내에서 처음 장과 나중에 보는 장이 제자리, 두 번 옮기지 않음.
- 고치기 전 엔진으로 새 시험을 돌려 실패하는 것을 확인했다.
- 실제 수업 파일(`3-01-1. 마이토콘드리아의 구조와 기능.html`, 엔진 주소만 이 PC로 바꾼 사본)로 교사 탭과 학생 탭을 이어 확인했다. QR 크게 보기, 칠판 판서(로컬·Supabase, 375px), 글꼴이 다른 학생의 배율 맞춤, 옛 브라우저 흉내 학생 화면의 그림·이름표·그림 설명·② 문장 위 동그라미.
- 새 문구(QR 단추, README 다섯 줄)는 korean-humanize 게이트를 거쳤다(`PPT to HTML/_workspace/2026-10-26-001-live`, exit 0).

## 확인 못 한 것과 위험

- 실제 갤럭시 탭·학생 휴대폰, 실제 전자칠판, 30명 규모에서는 보지 않았다. 사진 속 학생 기기가 옛 브라우저였는지 수업 중 편집이었는지는 가리지 못했다.
- 칠판 판서가 안 보였다는 증상의 원인은 찾지 못했다. 학생을 칠판으로 데려오는 것은 가장 그럴듯한 경로를 막은 것이다.
- 학생 글꼴이 교사보다 넓은 장은 여전히 조금 어긋날 수 있다. 근본 해결은 엔진에서 Pretendard 웹 글꼴을 불러 모든 기기 글꼴을 같게 하는 것이다. 모든 수업의 모양이 바뀌므로 선생님 결정이 필요하다.
- 수업 CSS 안(스타일시트)에 적은 `translate`는 옛 브라우저에서 맞추지 않는다. 편집기는 style 속성에만 적는다.
- `@2`로 공개하면 모든 수업 파일에 바로 들어간다.
