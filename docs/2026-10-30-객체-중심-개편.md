# 공명 사이트 객체 중심 개편 (2026-10-30)

- 브랜치: `ux-object-1030` (main `e593e68`에서 갈라져 `ux-fixed-1027`을 합친 뒤 고쳤다)
- 고친 사람: Claude Code(Claude Opus 5.5)
- 공개 사이트와 CDN 엔진(`@2`)은 그대로다. main에 합쳐 올려야 Pages가 바뀌고, 엔진은 새 `v2.*` 태그를 달아야 수업 파일에 반영된다.

## 왜 바꿨나

점검해 보니 공명 사이트는 할 일(태스크) 중심이었다. 메뉴가 「살펴보기」「제작하기」 같은 동사였고, 쪽마다 단계 설명과 단추가 먼저 나왔다. 실제 결과물은 깊숙이 있었다.

- 첫 화면: 15초 인트로가 화면을 차지했다. 무엇을 하는 도구인지는 바닥글 한 줄에만 있었다.
- 예시 수업 12개: 「제작하기」 맨 아래, PC 폭(1280px)에서 위에서 2,933px 아래에 있었다. 바꾼 뒤에는 첫 화면 786px 자리에서 시작한다.
- 강사 카드: Gemini 키 입력이 있는 양식이 먼저 나왔다. 보관함(카드)은 그 아래였다.

객체 중심(인스타그램처럼 결과물을 먼저 보여 주고, 결과물을 눌러 할 일을 고르는 방식)으로 바꿨다. 할 일은 「＋ 만들기」 하나로 모았다.

## 지킨 것

- 학생 입장: 첫 화면의 수업 코드 창과 `?join=코드` 주소를 그대로 둔다(수업 QR이 가리킨다). 강사 카드 쪽은 CSP 때문에 입장 스크립트를 싣지 않고 첫 화면 입장 창(`./#join-h`)으로 보낸다.
- 예시 수업과 AI별 비교 내용, `make.html#lessons`, `#comparison` 주소.
- 강사 카드의 저장 방식, 백업, 카드 파일 형식(`cards.js`의 계산 함수는 그대로, 화면 연결만 바꿨다).
- 바깥 자료는 `textContent`로만 넣는다. `innerHTML`을 쓰지 않는다.

## 2차 고침 (같은 날, 선생님이 4192 미리 보기를 보고 준 의견)

| 의견 | 고친 것 |
|---|---|
| 바탕색이 흰 카드와 상자를 묻어 버린다 | 쪽 바탕을 `--page:#E6EAEF`(서늘한 회색)로 바꿨다. 창과 칩의 종이색(`--paper`)은 그대로다. 회색 글자(`--mute`)는 새 바탕에서 대비 4.5:1을 넘게 `#5F5E59`로 조금 짙게 했다 |
| 「내 PPT로 만들기」 대신 「수업 HTML 만들기」와 「수업 대본 만들기」 두 단추를 같은 높이로 | 첫 화면, 머리 메뉴, 기능 쪽 끝 띠에 두 단추를 나란히 두었다. 수업 HTML은 흙색, 수업 대본은 청록으로 색을 나눴다. 「＋」 아이콘은 뺐다 |
| 머리 메뉴에 「수업」「기능」이 왜 있나, 둘이면 된다 | 머리 메뉴는 두 만들기뿐이다. 첫 화면은 로고, 기능 쪽은 기능 영상의 「자세히 보기」와 바닥글 「기능 자세히 보기」로 간다. 좁은 화면에서는 두 단추가 아래 막대가 되고, 첫 화면의 같은 단추는 숨긴다 |
| 오른쪽 위 「수업 코드」는 없애도 된다 | 머리에서 뺐다. 사이트로 들어오는 학생을 위해 입장 창은 바닥글 「수업 코드로 입장」으로 옮겼다. `?join=코드`와 `#join-h` 주소는 그대로 창을 화면 위쪽에 띄운다 |
| 강사 카드가 너무 아래에 숨어 있고 이름도 애매하다 | 쪽 이름을 「수업 대본 만들기」로 바꾸고 강사 카드는 그 안의 재료 이름으로 남겼다. 첫 화면에서는 「수업 대본」 구역을 기능 영상 바로 아래로 올리고 강사 카드 → 대본 한 장면 그림과 「예시 대본 보기」를 넣었다 |
| 바닥 구석의 「공명 인트로 보기」 | 기능 영상 줄 맨 앞에 「소개 영상」(15초, `assets/intro/intro-1080p.mp4`)으로 옮겼다 |
| 「만들기」「제작하기」가 뒤섞였다 | 「제작하기」를 모두 걷었다. 제목은 「수업 HTML 만들기」「수업 대본 만들기」로 맞췄다 |
| 대본 HTML도 수업 HTML처럼 그 안에서 바로 고치게 | 대본 뷰어에 「편집」을 넣었다. 글(대사, 질문, 연출, 장 제목, 대본 제목)을 눌러 고치고 「HTML 저장」으로 고친 대본 파일을 받는다. 태그, 대기 시간, 강사 이름, 장 id는 지킨다 |

- 예시 대본: `tools/site.mjs`가 `skills/lecture-script/references/examples/v3-high-bio-script.html`을 `_site/scripts/`에 넣으며 뷰어를 사이트 안의 `../script-viewer/`로 부른다. 그래서 사이트를 올리면 예시 대본에는 바로 「편집」이 생긴다. 저장한 파일은 뷰어 주소를 CDN으로 되돌려 내려받은 뒤에도 열린다.
- AI가 새로 쓰는 대본 파일은 CDN `@2`의 뷰어를 부른다. 그 파일에 「편집」이 생기려면 `v2.*` 태그를 새로 달아야 한다(엔진도 함께 나간다). 태그는 선생님 확인 뒤에 단다.
- 윤문 게이트: `PPT to HTML/_workspace/2026-10-30-002-bf82`, light, 변경률 4.5%, exit 0. 연결어미 뒤 쉼표 셋을 빼고 긴 관형구가 겹친 소개 문장을 둘로 나눴다.
- 확인: 단위 테스트 113개(대본 편집 테스트 3개 추가) 통과. 첫 화면, 수업 대본, 기능, 제작 안내, 예시 대본을 320·375·768·1024·1440px에서 찍어 가로 넘침이 없었다. 내장 브라우저에서 예시 대본을 편집해 제목, 대사, 질문, 장 제목을 고치고 저장 파일을 다시 읽어 형식 오류 0, 장 12개를 확인했다.
- 확인 못 한 것: 실제 휴대폰과 전자칠판에서 대본 편집(한글 입력기의 Enter), 200% 문자 확대.
