# 공명 기획의도

## 1. 해결하려는 문제

| 문제 | 교실에서 겪는 일 |
|---|---|
| 만들기 어렵고 결과가 일정하지 않다 | AI마다 화면과 활동이 다르게 나오고 판서나 넘기기 같은 기본 기능이 빠지기도 한다. 고칠 곳이 생기면 AI에 다시 부탁해야 한다. |
| PPT가 정지된 그림에 머문다 | 값에 따라 달라지는 개념도 그림 몇 장으로 보여 줄 뿐이다. 학생이 변수를 바꿔 결과를 살펴볼 수 없다. |
| 전자칠판 판서가 불편하고 남지 않는다 | 펜과 넘기기 모드를 오가야 한다. 장을 넘기거나 파일을 닫으면 판서가 사라지고 반마다 따로 남기기 어렵다. |
| 교사 화면과 학생 기기가 따로 논다 | 학생은 칠판을 바라보는 데 그치고 교사는 반 전체의 생각이 어디에 모였는지 확인하기 어렵다. |

## 2. 핵심 기능

공명은 교사가 쓰던 AI(ChatGPT, Gemini, Claude)에 프롬프트 한 줄과 수업 자료(PPT, 교사용 교과서 PDF)를 건네면 전자칠판 수업용 HTML 파일 하나를 만들어 준다.

- **HTML 생성 및 편집**: AI가 교과와 차시, 학생이 헷갈리는 지점, 넣을 기능을 묻고 설계표를 확인받아 파일을 만든다. 완성된 파일은 「편집」에서 바로 고치고, 자동 점검이 넘침과 부품 오류를 찾는다.
- **익스플로라그램**: 탐구 가능한(Explore) 다이어그램(Diagram)이다. 학생이 값을 바꾸거나 점을 끌어 옮기면 그림과 수치, 그래프가 계산되어 함께 바뀐다.
- **실시간 수업**: 코드 6자리나 QR로 들어온 학생 기기가 교사 화면을 따라온다. 슬라이더 값과 퀴즈, 투표 응답이 이름 없이 교사 화면에 모이고 교사 판서도 학생 화면에 보인다.
- **전자칠판 기능**: 펜을 든 채로 장을 넘기고 단추를 누른다. 판서는 장별, 반별로 저장되고 칠판과 레이저, 타이머, 발표자 뽑기를 함께 쓴다.

## 3. 기대 효과

- 교사는 새 도구를 따로 익히지 않고 쓰던 AI와 수업 자료로 수업 파일을 만들고 파일 안에서 직접 고친다.
- 학생은 설명을 듣는 데서 그치지 않고 직접 값을 바꾸며 원리를 찾고 자신의 답을 보낸다.
- 교사는 반 전체의 응답을 함께 보며 다음 설명과 활동을 정할 수 있다.

## 4. 웨일 스페이스 연계 (분야 1 · 수업 지원·학습 활동)

엔진이 HTML 파일 하나에 들어 있어 연결부만 더하면 웨일 스페이스 서비스와 이어진다.

| 웨일 스페이스 | 공명과 잇는 방법 |
|---|---|
| 네이버 웨일 | **지금** 수업 파일이 웨일 브라우저와 웨일북, 전자칠판에서 설치 없이 열린다. |
| 웨일 클래스 | **지금** 「학생용 파일 저장」으로 받은 파일을 올리면 수강 학생만 열고 코드로 참여한다. 교과서 그림이 든 자료를 인터넷에 공개하지 않아도 된다. |
| 수업관리 | **지금** 탭 전송으로 수업 주소를 학생 노트북에 한 번에 띄운다. |
| 웨일 스페이스 어드민 | **추후** 공개 서버(Supabase Realtime) 대신 웨일 스페이스 계정과 학급 명단으로 수업 방을 연다. |
| 팀보드 | **추후** 학생 값 분포와 단답을 팀보드로 보내 모둠 토의에 이어 쓴다. |
| 웨일 UBT | **추후** 확인 문제를 웨일 UBT 문항으로 내보낸다. |
| 웨일온 | **추후** 원격 수업에서 웨일온 화면과 학생 기기를 함께 맞춘다. |
